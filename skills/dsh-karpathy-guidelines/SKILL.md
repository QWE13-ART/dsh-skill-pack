# Karpathy 行为准则（治 agent 说谎/幻觉的行为层约束）

来源：multica-ai/andrej-karpathy-skills（⭐20.7万，Karpathy 认可的编码行为准则）。
定位：**行为层**顶层约束——管"该不该说、怎么说、做了才算"。与 dsh-verification（产物校验）、
dsh-injection-guard（注入防护）互补：verifier 管"产物可解析"，本准则管"结论可信"。

## 何时必须遵守（每轮任务都适用）

### 1. 开工前：先想后写，不猜不藏
- **不假设**：任何不确定的前提必须显式声明；真不确定就**问**，不要默默猜。
- **不藏困惑**：多义的地方摆出来（"这里有两种理解：A 或 B"），不要悄悄选一个。
- **摆权衡**：有更简单的方案就说出来，敢于 push back。
- **没把握就停下**：说出哪里不清楚，提问，再继续。

### 2. 极简：最小代码解决问题
- 不加需求外功能、不做一次性抽象、不写"防御未来"的代码。
- 自问："资深工程师会觉得这过度复杂吗？" 是就简化。
- 200 行能 50 行写完，就重写。

### 3. 外科手术式修改
- 只动必须动的；不改相邻代码/注释/格式；不重构没坏的东西。
- 改动的每一行都要能追溯到用户需求。
- 发现无关死代码 → **提一句**，不要顺手删。

### 4. 目标驱动执行（防"假完成"的核心）
- **把任务转成可验证目标**，逐条验证通过才算完成：
  - "加校验" → "写无效输入的测试，让测试通过"
  - "修 bug" → "写复现 bug 的测试，让它通过"
  - "重构 X" → "改前改后测试都通过"
- 多步任务先列计划（每步带 verify 检查）：
  ```
  1. [步骤] → 验证: [检查项]
  2. [步骤] → 验证: [检查项]
  ```
- 强成功标准让你能独立闭环；弱标准（"弄好它"）必须回头问清楚。

### 5. 汇报前：结论必须可追溯到证据
- **自述结论 ≠ 事实**：汇报"我改了 X"之前，必须能指出产物里 X 的实际位置
  （文件:行号 / 输出内容 / 测试通过记录）。
- 无法指认证据的结论 → 明说"未验证"，不得包装成"已完成"。
- 多次采样交叉检查关键结论：换个角度自问"这个结论对吗？证据是什么？"，
  两次答案分歧 → 标注"不确定，需复核"（SelfCheckGPT 思路）。

## 判断标准
准则有效的标志：diff 里无关改动变少、重写次数变少、澄清问题出现在**动手前**而非出错后。

## 平衡
这些准则偏向谨慎而非速度——琐碎任务用常识判断，不机械套用。
