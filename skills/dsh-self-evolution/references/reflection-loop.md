# 认知调试循环（Reflection & Cognitive Debugging Loop）

> 移植自 alphaparkinc/genpark-agent-self-reflection-loop-skill（MIT）。
> 定位：输出层反思——与 autotelic-evolution（教训沉淀）、dsh-verifier（产物验证）
> 互补：本技能管"输出本身站不站得住"，verifier 管"产物做没做对"。

## 何时使用

- 刚生成重要输出（方案/结论/代码），自我感觉"不太对但说不出哪不对"
- 回答涉及数字/事实/承诺，需要二次审查
- 被用户指出错误后，需要系统性修正（而不是改个表面）
- 逻辑步骤多、容易自相矛盾的输出

## 循环流程（4 步，必要可多轮）

### 1. 反思（Reflect）
对刚生成的输出逐条自问：
- 我是否**假设**了什么没验证？列出假设清单
- 我的**逻辑链**哪一环最弱？（前提→推论→结论）
- 是否**过度自信**？置信度打分（0-1），低于 0.6 的结论必须标注
- 是否有**矛盾**？（前后不一致/与已知事实冲突）

### 2. 定位（Locate）
把问题归类，别只描述现象：
- `认知偏差`：锚定（被第一个念头带偏）/ 确认偏误（只找支持自己的证据）/
  可得性（凭印象不查证）
- `逻辑谬误`：滑坡 / 以偏概全 / 虚假二分
- `事实错误`：数字/引用的来源没核

### 3. 修正（Refine）
- 逐条重写有问题的部分，**写出修正理由**（不静默改）
- 无法确证的部分 → 明确降级为"假设/待验证"，不得保持"确定"语气
- 若需要外部验证 → 指出验证手段（搜索/运行测试/问用户）

### 4. 复检（Verify）
- 对照修正前的怀疑点逐条确认是否解决
- 置信度重打分：修正后仍 <0.6 的结论 → 明说"不确定"
- 单次循环未解决 → 再跑一轮（最多 3 轮，超过即上抛给用户）

## 与既有能力的分工

| 场景 | 用 |
|---|---|
| 输出可疑，自查 | 本技能（反思循环）|
| 产物验证（文件/执行）| dsh-verifier |
| 失败教训沉淀 | autotelic-evolution |
| 开工前想清楚 | dsh-brainstorming / dsh-karpathy-guidelines |

## 边界

- 本技能是**思维流程**，不执行任何外部动作（只读自查）
- 修正必须留痕（输出前后对比），防止"静默改"掩盖问题
